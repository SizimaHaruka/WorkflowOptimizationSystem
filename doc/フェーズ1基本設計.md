# 合理化検討ワークフロー フェーズ1基本設計

作成日: 2026-07-15
対象: MVP フェーズ1（案件受付から調査範囲確定まで）

## 1. 実装範囲

`軽量Webシステム検討.md` のフェーズ1に沿って、以下を実装する。

- 案件台帳
- F01 案件受付票
- F02 調査計画票
- F10 課題・宿題管理表
- F11 意思決定記録
- G0 調査着手、G1 範囲確定のゲート判定
- 案件ステータス履歴と要対応ダッシュボード

認証、添付ファイル、F03以降の帳票、追跡ビュー、通知、CSV/PDF出力はフェーズ1の対象外とする。

## 2. 画面と導線

```text
要対応ダッシュボード
  └─ 案件一覧 ─ 案件登録 ─ 案件詳細
                               ├─ F01 案件受付票
                               ├─ F02 調査計画票
                               ├─ F10 課題・宿題（一覧・登録・更新）
                               ├─ F11 意思決定記録（一覧・登録）
                               ├─ G0 判定
                               └─ G1 判定
```

案件詳細を案件単位の作業起点とする。F10 と F11 は将来、他フェーズからも同じ案件IDを指定して追加できる共通機能として扱う。

## 3. データ設計

|テーブル|主な保持内容|設計意図|
|---|---|---|
|`Cases`|案件番号、名称、依頼部署・依頼者・責任者、受付日、希望時期、優先度、状態、概略範囲|検索・一覧・進捗管理で使う項目を列として保持する|
|`CaseForms`|案件ID、帳票種別、版、状態、帳票本文JSON|帳票固有の項目変更に耐える。フェーズ1ではF01/F02を保存する|
|`ActionItems`|案件ID、No.、区分、内容、担当、期限、状態、回答・処置|F10の課題・宿題を案件横断でも確認可能にする|
|`DecisionRecords`|案件ID、決定No.、決定内容、根拠、影響、承認欄|F11の判断を追加専用で記録する|
|`GateReviews`|案件ID、ゲート、判定、判定者、判断日、コメント、チェック結果JSON|G0/G1の根拠と差戻し履歴を残す|
|`CaseStatusHistories`|変更前後の状態、変更者、日時、コメント|案件の状態変更を監査可能にする|

案件番号は `DX-YYYY-NNNN` とし、案件登録時に受付年・連番から自動採番する。DBでは案件番号、案件ID＋帳票種別＋版、案件ID＋課題No.、案件ID＋決定No.を一意にする。

## 4. 帳票JSONの扱い

F01とF02は検索に必要な骨格を`Cases`に同期し、フォーム固有項目を`CaseForms.ContentJson`へ保存する。

- F01の概略対象範囲は、保存時に`Cases.ScopeSummary`へも同期する。
- F02の関係者、調査ステップ、必要資料はJSON内の配列として保持する。
- 帳票は初期版を`Version = 1`として保存する。ゲート承認・差戻し時の版上げは次フェーズで追加する。

## 5. G0/G1の判定

|ゲート|承認の必須チェック|承認後のステータス|
|---|---|---|
|G0 調査着手|問題、依頼者、案件責任者、概略範囲が明確|調査中|
|G1 範囲確定|開始点、終了点・成果物、対象部署、除外範囲が合意済み|As-Is確認中|

G1の承認は、G0が承認済みの場合だけ許可する。差戻し時は、チェック結果とコメントを保存し、案件を補助ステータスの`差戻し`にする。ゲートによる状態変更も通常の状態変更と同様に`CaseStatusHistories`へ記録する。

## 6. ステータス変更

案件登録時の初期状態は`受付`とする。案件詳細からの明示的なステータス変更では、変更者とコメントを記録する。認証導入前のMVPでは、変更者名を入力する。認証導入時にはログインユーザーへ置き換える。

## 7. 開発DBと初期化

開発時はSQL Server LocalDBの`Dxpmt`データベースを利用する。開発環境でのアプリ起動時に`EnsureCreated`を実行し、テーブルを作成する。本番DBのスキーマ適用は、フェーズ4でEF Coreマイグレーションと配備手順を整備してから行う。

## 8. 次フェーズへの引継ぎ

フェーズ2では、F03/F04/F05と、`WorkItems`・`Problems`・`TraceLinks`を追加する。フェーズ1の`Cases`、`CaseForms`、`ActionItems`、`DecisionRecords`、`GateReviews`は、そのまま追跡と判断履歴の基盤として利用する。
