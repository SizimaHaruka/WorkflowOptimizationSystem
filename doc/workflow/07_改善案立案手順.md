# 改善案立案手順

## 目的
特定の製品やシステムを前提とせず、問題に対する複数の改善案を作成する。

## 使用帳票
- F05 問題・課題一覧
- F06 改善案評価票
- F11 意思決定記録

## 検討順序
1. 作業を廃止できないか
2. 頻度、粒度、要求品質を下げられないか
3. 他作業と統合できないか
4. ルール、帳票、項目を標準化できないか
5. 情報源を一元化できないか
6. 既存機能で対応できないか
7. 一部を自動化できないか
8. 新規システム・大規模改修が必要か

## 手順
1. 対象問題と原因仮説を確認する。
2. 制約条件を確認する。
3. 検討順序に従って複数案を作る。
4. 各案で変更する作業、役割、情報、ルールを記載する。
5. 効果が生じる仕組みを説明する。
6. 他部署への負荷転嫁、品質、安全、統制への影響を確認する。
7. 前提条件と残る問題を記載する。
8. 不採用案も理由を残す。
9. 評価対象案を選定する。

## 完了条件
主要問題に対し、比較可能な複数案があり、前提と影響範囲が記録されている。
