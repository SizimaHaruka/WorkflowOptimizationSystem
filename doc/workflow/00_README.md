# 合理化検討業務パッケージ（たたき台）

## 目的
業務合理化・システム化検討を、案件受付から実施後評価まで一貫した手順で行うための標準業務フロー、作業手順、帳票を定義する。

## 標準フロー
```text
案件受付
→ 事前調査・対象範囲設定
→ As-Isヒアリング
→ 現状業務フロー作成
→ 問題分析
→ 改善案立案
→ 効果・実現性評価
→ To-Be設計
→ 要求事項化・実施判断
→ 実施後評価
```

## 基本原則
1. システム化を前提にせず、現状業務と問題を先に確認する。
2. 現象、原因、影響、対策を混同しない。
3. 規程上の手順と実際の運用を区別する。
4. 通常処理だけでなく、例外、異常、待ち、手戻りを確認する。
5. 改善案は、廃止、簡素化、統合、標準化、一元化、既存機能、自動化、新規システム化の順に検討する。
6. 要求事項は、元となる作業、問題、改善案へ追跡可能にする。
7. ヒアリング時は現場名称を使用し、ID付与と表記統一は整理段階で行う。

## 標準成果物
|フェーズ|成果物|
|---|---|
|案件受付|案件受付票|
|範囲設定|調査計画票|
|As-Is調査|作業ヒアリング票|
|構造化|As-Is業務フロー|
|問題分析|問題・課題一覧|
|改善案立案・評価|改善案評価票|
|To-Be設計|To-Be作業定義票、To-Be業務フロー|
|要求事項化|要求事項一覧、意思決定記録|
|実施後評価|効果確認票|
