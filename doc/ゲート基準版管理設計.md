# ゲート基準版管理設計

## 1. 目的

版管理の対象は保存操作ではなく、ゲートで関係者が合意した成果物の基準状態とする。後続工程で参照した前提、意思決定時の根拠、差戻し後の変更内容を再現できるようにする。

## 2. 基本方針

- 通常保存は下書きの更新であり、版番号を増やさない。
- ゲートの**承認**時だけ、対象成果物の不変スナップショットを基準版として保存する。
- 差戻し時はゲート判定・理由を記録するが、基準版は作成しない。
- 差戻し後に修正し、同じゲートを再承認した時点で次の基準版を作成する。
- F10は継続管理台帳のため版管理しない。F11は判断そのものを記録するADRであり、訂正は元記録を消さず、新しい意思決定記録で扱う。

## 3. ゲートと基準版対象

|ゲート|確定する基準成果物|
|---|---|
|G0 調査着手|F01 案件受付票|
|G1 範囲確定|F02 調査計画票|
|G2 As-Is確定|F03 作業ヒアリング票、F04 業務フロー整理票|
|G3 改善案選定|F05 問題・課題一覧、F06 改善案評価票|
|G4 To-Be確定|F07 To-Be作業定義票|
|G5 実施判断|F06 改善案評価票、F08 要求事項一覧|
|G6 案件終結|F09 効果確認票|

F03、F05〜F08は複数明細で構成されるが、レコードごとではなく帳票全体の集合を1つの基準版として保存する。

## 4. データ設計

`GateBaselines` に、案件、ゲート判定、帳票種別、帳票内連番、JSONスナップショット、確定者、確定日時を保存する。

- 一意制約: 案件ID、帳票種別、版番号
- ゲート判定IDを保持し、どの承認で確定した基準版かを追跡する
- 基準版は更新・削除しない

既存の `CaseForms` は現在の編集可能なフォーム本文を保持する。基準版は `GateBaselines` に分離するため、下書き保存で版が増えない。

## 5. UI

- ゲート判定画面に、その承認で確定される帳票を表示する。
- 案件詳細から「基準版履歴」を開き、帳票、版、ゲート、確定者、確定日時、保存内容を確認する。
- 手動の一括確定操作は設けない。

## 6. F10・F11の扱い

- F10: 状態・担当・期限を継続的に更新する管理台帳。ゲート基準版の対象外とする。
- F11: 重要な判断、範囲変更、要求変更のADR。原則として追記型とし、訂正が必要な場合は元記録への参照を持つ後続記録で置き換える。
